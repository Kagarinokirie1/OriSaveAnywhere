# 暂停菜单与存档系统

本文记录「随时存档」Mod 所依赖的暂停（ESC）菜单结构、菜单项交互链路，以及游戏自带的存档管线。
代码逻辑结论来自 `Decompiled/ISIL/IsilDump/__mainWisp/` 下的 ISIL 反汇编；界面结构结论来自
对场景资源 `Assets/scenes/inGameUI.unity` 的解析（见第一节）。

## 一、界面结构是怎么拿到的

暂停菜单不是运行时用代码拼出来的，而是 `inGameUI.unity` 场景里的预制实例，字段名/节点名只存在于
序列化资源里，反编译的 C# 只能给出类结构。定位与解析流程：

1. `oriwotw_Data/globalgamemanagers` 里存着构建场景列表，其中 `Assets/scenes/inGameUI.unity` 是常驻的游戏内 UI 场景。
2. 按构建顺序该场景对应 `oriwotw_Data/level303`（该文件里能直接搜到 `MenuScreenManager`、`CleverMenuItem` 等类型名）。
3. 场景文件是 LZ4 分块压缩的，普通文本搜索拿不到 MonoBehaviour 字段；用 AssetStudio（`D:\project\.tools\Unity\AssetTools\AssetStudio`）确认类名，
   再用 UnityPy 解压后手工解析 `GameObject` / `Transform` 的序列化数据，重建节点树。
4. `MonoBehaviour.m_Script` 指向的 `MonoScript` 在 `globalgamemanagers.assets`（fileID=1），据此把每个组件还原成真实类名。

> 注意：UnityPy 自带的 `GameObject` 类型树在 2018.4 IL2CPP 上会读错（少算 4 字节），本次是手工按
> 「组件数组 → m_Layer → 一个恒为 1 的 int → 名称 → tag → isActive」的顺序解析的。

## 二、暂停菜单节点结构（`inGameUI.unity`）

```
pauseScreen2                 [Transform, PauseScreen, SoundHost, CleverMenuItemSelectionManager]
  skipFader                  [Transform, ...]
  faderRoot                  [Transform]
    items                    [Transform, CleverMenuItemLayout]        <- 菜单项容器
      resumeGame             [Transform, CleverMenuItem]              <- 继续
        resume               [Transform, MessageBox, TextBox]        <- 文字
        glows / glowsTimelines / pressed ...
      backup saves           [Transform, CleverMenuItem]              <- 备份游戏存档
      quick access           [Transform, CleverMenuItem]
      options                [Transform, CleverMenuItem]              <- 选项
      exitGame               [Transform, CleverMenuItem, InLoremasterReplayCondition, NotCondition]
      skip / abandonChallange / exitReplay / backups ...
```

要点：

- `PauseScreen.NavigationManager` 就是 `pauseScreen2` 上的 `CleverMenuItemSelectionManager`（`PauseScreen` 字段偏移 `0x38`）。
- 所有菜单项是 `items` 的直接子物体，每个只挂一个 `CleverMenuItem`；显示文字是子物体上的 `MessageBox` + `CatlikeCoding.TextBox`。
- `items` 上的 `CleverMenuItemLayout` 负责纵向排布。
- 菜单项位置实测：`resumeGame` y≈0、`options` y≈-1.64、`exitGame` y≈-3.22（间距 1.62）。
- `exitGame` 额外挂了 `InLoremasterReplayCondition` + `NotCondition`，即「回味模式里隐藏退出项」。

## 三、菜单项交互链路

### 3.1 按下时发生什么

`CleverMenuItem.OnPressed()`（`CleverMenuItem.txt`）：

```
if (!IsActivated) { 记异常; return; }
if (Pressed != null) Pressed.Perform(null);     // ActionMethod
if (PressedCallback != null) PressedCallback(); // System.Action
```

所以往 `PressedCallback` 挂一个委托即可让新菜单项只执行自定义逻辑；同时把 `Pressed` 置空以屏蔽克隆来的原动作。

### 3.2 可见性与可选中性

- `CleverMenuItem.get_IsVisible()`：`Visible == null` 直接返回 `true`，否则取 `Visible.Evaluate()`。
- `CleverMenuItem.get_IsActivated()`：同理，`Activated == null` 视为可用。
- 因此克隆体把 `Visible` / `Activated` 置空后，既不依赖任何条件，也能被布局与导航正常处理。

### 3.3 导航

`CleverMenuItemSelectionManager.MoveSelection(forward, step)` 完全按下标在 `m_menuItems` 里前后移动并跳过不可用项
（`CleverMenuItemSelectionManager.txt`）。`AddMenuItem(item)` 只是 `m_menuItems.Add(item)`，
所以追加后手柄/键盘都能选中新按钮。

### 3.4 文字

`MessageBox.RefreshText(replace, with)`（`MessageBox.txt`）的分支：

- `MessageProvider != null`：走本地化文本。
- `MessageProvider == null` 且 `OverrideText != ""`：直接 `TextBox.SetText(OverrideText)`。

因此把 `MessageProvider` 置空、设置 `OverrideText` 再调用 `RefreshText()` 就能显示自定义文字。

## 四、纵向排布 `CleverMenuItemLayout.Sort()`

`CleverMenuItemLayout`（`CleverMenuItemLayout.txt`）字段：`MenuItems`（`List<CleverMenuItem>`）、`VerticalAlignment`（`Top=0 / Center=1 / Bottom=2`）。

`Sort()` 逻辑：

1. 先按 `MenuItems` 顺序遍历，跳过 `!IsVisible` 的项，把可见项**绝对**摆到 `localPosition = (0, -累计高度, 0)`，累计量按每项自身的 `CleverMenuItem.Space` 递增。
2. 若 `VerticalAlignment == Center`，再把整块按总高度的一半向上平移；`Bottom` 同理整体上移一个总高度。

因为第一步是绝对赋值，`Sort()` 可以重复调用而不会累积偏移。`OnEnable` 里会自动调用一次，
所以往 `MenuItems` 里追加新项后，手动调用一次 `Sort()` 即可立即生效。

## 五、游戏自带的存档管线

### 5.1 触发入口

存档点走的是 `CheckpointFunctionality.CreateCheckpoint(doPerformSave, respectRestrictCheckpointZone)`
（`CheckpointFunctionality.txt`），它最终调用：

```
GameController.Instance.CreateCheckpoint(doPerformSave, respectRestrictCheckpointZone)
```

`GameController.CreateCheckpoint`（`GameController.txt`）：

```
if (respectRestrictCheckpointZone && !RestrictAbilityController.CanCreateCheckpoint()) return;
if (DisableCheckpoints) return;
if (LoreMasterReplayActive) doPerformSave = false;
Game.Checkpoint.Events.OnPreCreate?.Call();
if (doPerformSave) {
    UberStateController.CurrentStateValueStore.NotifyPresaveObservers();
    m_saveSnapshot = UberStateController.CurrentStateValueStore.ToByteArrayWithCopy();
    SaveGameController.PerformSave();
}
Game.Checkpoint.Events.OnPostCreate?.Call();
```

`respectRestrictCheckpointZone = false` 即可绕过「禁止存档区域」（Boss 战、逃亡段等）。

### 5.2 落盘与备份

`SaveGameController.PerformSave()`（`SaveGameController.txt`）：

```
if (!CanPerformSave()) return;
PerformBackOutAction.ClearAbandonChallangeCondition();
SaveSlotsManager.CurrentSaveSlot.FillData();
SaveSlotBackupsManager.CreateCurrentBackup();          // 生成「备份游戏存档」
SaveSlotsManager.BackupIndex = -1;
SaveToFile(SaveSlotsManager.CurrentSlotIndex, -1,
           UberStateController.CurrentStateValueStore, clearSnapshot: true, shouldNotifyObservers: true);
```

即：只要走 `GameController.CreateCheckpoint(true, ...)`，就会**同时**写主存档并生成一条备份存档，
与在游戏里踩存档点的结果完全一致，备份会出现在 ESC 菜单的「备份游戏存档」列表里。

### 5.3 备份存档的节流（实测踩过的坑）

`SaveSlotBackupsManager.CreateCurrentBackup()`（`SaveSlotBackupsManager.txt`）虽然每次都被调用，
但内部有节流，唯一会**直接跳过备份**的分支是：

```
if (Instance.m_gameJustLoadedDelay > 0) return;   // 字段偏移 0x60
...
Instance.m_gameJustLoadedDelay = 10f;             // 成功路径结束后重置为 10 秒
```

`Update()` 会逐帧递减这个延迟，`SetupGameLoadedDelay(delay)` 在读档后也会设置它。
因此**刚读档后的一段时间内手动存档不会产生新备份**，表现为「ESC 菜单 → 备份游戏存档里看不到刚存的档」。
`m_lastSaveTime` / `TIME_BETWEEN_SAVES` 只影响 `LastBackupType`（2 或 3），两条分支最终都会写备份。

本 Mod 的「每次存档都生成备份存档」选项就是在存档前把 `Instance.m_gameJustLoadedDelay` 置 0，
绕过这段节流。注意备份位只有 `SaveSlotBackup.MAX_BACKUPS = 10` 个且会轮换，
频繁存档会把较旧的备份挤掉（游戏自身用 `RESERVED_RECENT_SAVES = 3` 保留最近三条）。

### 5.4 复活点的贴地兜底

`InvisibleCheckpoint.GetSeinGroundPosition(out pos, target, castOffsetScalar = 1)`
内部会向下做一次射线找地面；游戏自带存档点在找不到地面时**直接放弃创建检查点**并打错误日志
（`CheckpointFunctionality.txt` 第 260~285 步）。
实测部分地形下它会返回 false，导致手动存档后复活点没有更新、读档仍回到旧存档点。
本 Mod 的兜底顺序是：

1. `InvisibleCheckpoint.GetSeinGroundPosition`；
2. 失败时用 `CharacterPlatformMovement.GroundRayHit` / `GroundRayPoint`（角色自己的地面射线落点）；
3. 再失败则退化为玩家当前位置。

### 5.5 复活点是怎么记录的

`CheckpointFunctionality.CreateCheckpoint` 在角色位置模式下：

```
pos = InvisibleCheckpoint.GetSeinGroundPosition(out ground, Characters.Current.position, 1f) ? ground : 失败
PlatformMovement.OverridePositionNextSave(pos);   // 标记「下次序列化用这个位置」
... 之后才 GameController.Instance.CreateCheckpoint(...)
```

`PlatformMovement.OverridePositionNextSave(Vector3)`（`PlatformMovement.txt`）会把位置缓存下来，
在 `CreateCheckpoint` 内部的 `NotifyPresaveObservers()` 阶段写进 UberState。
顺序必须是「先 Override，再 CreateCheckpoint」。

## 六、其它可用入口

| 入口 | 说明 |
| --- | --- |
| `PauseScreen.Instance` | 暂停界面单例，`OnInstantiate` 时赋值、`OnDestroy` 时清空。 |
| `PauseScreen.NavigationManager` | 暂停菜单的 `CleverMenuItemSelectionManager`。 |
| `PauseScreen.Items` | 菜单项容器 Transform（实测即 `faderRoot/items`）。 |
| `MenuScreenManager.CurrentScreen` / `IsVisible(Screens)` | 判断当前打开的是哪个界面。`Game.UI.Menu` 取实例。 |
| `GameController.SaveGameController.CanPerformSave()` | 存档前置检查。 |
| `SaveSlotsManager.CurrentSaveSlot` / `CurrentSlotIndex` | 当前存档槽。 |
